## Backend Connection

The app reads the backend URL from:

```text
API_BASE_URL
```

### Physical Android device

The phone must be able to reach the development computer.

```bash
flutter run --dart-define=API_BASE_URL=http://<COMPUTER_IPV4>:8080
```

Do not use `127.0.0.1` for the PC backend on a physical phone.

If the local router assigns the PC a new IPv4 address after reconnecting, rerun the app with the new reachable backend address.

### Android emulator

```bash
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8080
```

## Finance Behavior

### Transactions

- Income increases balance.
- Expense decreases balance.
- Editing/deleting a transaction refreshes the dependent wallet/dashboard/budget state.
- Transaction forms prevent unsafe double submission.
- Delete/discard confirmation uses the shared SmartWallet confirmation dialog.

### Budgets

- Current month is the earliest navigable/creatable budget month.
- Budget details show real spent, remaining and progress.
- Related Expenses show only transactions actually counted for that budget.
- Empty and API-error states are distinguished.
- Warning state follows the user's warning preference/threshold.

### Planned Expenses

- New plans cannot select a past due date.
- Existing unpaid items may display as overdue when time passes.
- Creating a plan does not immediately change balance.
- Paid/Cancelled records remain in their corresponding history tabs.
- Mark as Paid creates the real transaction through the backend atomic operation.
- Transactions generated by Mark as Paid are displayed as read-only in Transaction Details so the Paid plan and actual financial record cannot diverge.

### Dashboard

Home displays real backend-calculated data:

- current balance
- Safe to Spend
- budget warning
- Upcoming Expenses count/total
- Weekly Insights summary
- recent transactions

### Weekly Insights

The detail view contains:

- spending comparison
- highest spending category
- budget performance
- upcoming planned expenses due in the next 14 days

No fake percentage is displayed when a previous-week comparison cannot be computed meaningfully.

## Session Security

- Access token is kept in memory.
- Refresh token is stored with Flutter Secure Storage.
- Raw tokens and passwords must never be logged.
- Failed network restoration must not silently invent an authenticated session.
- A temporary backend/network failure is different from an invalid refresh token.
- Logout revokes the backend refresh token when possible and clears authenticated local state.

## Error and Navigation Behavior

Forms and details screens must remain usable after:

- validation errors
- API/network failures
- cancelled confirmation dialogs
- failed save/delete operations

Async controllers guard disposed state, loading flags are reset safely, and shared confirmations avoid trapping the route behind an invisible modal.

## Security Rules

Never commit or share:

- passwords
- access tokens
- refresh tokens
- verification codes
- password-reset codes or tokens
- SMTP credentials
- database credentials
- JWT signing secrets

The Flutter app never contains database credentials or the JWT signing key. It communicates only with the SmartWallet REST API.
